## 1. Executive Summary & Core Architectural Principle

### 1.1 Core Principle: Local AST Knowledge Base & Semantic Understanding Engine
The SDLC-Agents-4-Enterprise platform uses Pega Server **ONLY** for fetching rule definitions and deploying verified changes. **ALL rule parsing, expression AST evaluation, workflow simulation, decision logic evaluation, and knowledge graph construction are executed LOCALLY inside our Node.js Hono Backend & PostgreSQL Database (`sa4e_db`)**.

- **Pega Platform**: Remote Target System (Exposes REST Service Package `KiroAgents`).
- **Node.js Hono Backend**: Local Intelligence Core (`PegaRuleAstParser`, `PegaLogicNormalizer`, `PegaRuleFetcherService`, `expression/`, `workflow/`, `decision/`, `ui/`, `security/`).
- **PostgreSQL Database**: Knowledge Base (`knowledge_entries` with 66 KB rows, `graph_nodes` with 33 Code Entity nodes).

## 3. Endpoints & Interface Specifications

### Service 1: `GET /api/v1/rules/{insKey}`
- **Purpose**: Fetch 100% complete rule XML/JSON definition by `pzInsKey` into local KB.
- **Query Params**: `insKey` (`string`).
- **Response**: `{ "pxObjClass": "...", "pyRuleName": "...", "pyClassName": "...", "pySteps": [...] }`.

### Service 2: `POST /api/v1/rules/query`
- **Purpose**: Query rule using 3 core identifiers (`pxObjClass` + `appliesTo` + `pyRuleName`).
- **Request Body**:
  ```json
  {
    "pxObjClass": "Rule-Obj-FlowAction",
    "appliesTo": "TGB-HRApps-Work-Candidate",
    "pyRuleName": "CollectCandidateDetails"
  }
  ```
- **Response**: Full 27KB+ JSON definition of the matched rule instance.

### Service 3: `GET /api/v1/rules/list`
- **Purpose**: List all rules in an Application / RuleSet scope for complete crawling.
- **Response**: `{ "rules": [ { "insKey": "...", "pxObjClass": "...", "pyRuleName": "..." } ] }`.

### Service 4: `POST /api/v1/rules/save`
- **Purpose**: Save/Update Pega Rule generated by AI DEV Agent after local AST verification.
- **Request Body**: Complete Pega Rule JSON object.

### Service 5: `POST /api/v1/rules/checkout`
- **Purpose**: Lock control (checkout/checkin into private ruleset).
- **Request Body**: `{ "insKey": "...", "action": "CHECKOUT" }`.

### Service 6: `POST /api/v1/rules/test`
- **Purpose**: Execute scenario unit test suite for QA Agent verification on remote server.
- **Request Body**: `{ "testSuiteID": "...", "ruleInsKey": "..." }`.

## 4. Local AST Engine Specifications (`backend/src/modules/pega/`)

1. **`expression/` (Pega Expression Language Parser)**:
   - Tokenizes and parses Pega clipboard expressions (`.Property`, `@function(args)`, `.AND.`).
   - Evaluates expressions against local `ClipboardContext` in-memory.

2. **`workflow/` (Workflow Interpreter Engine)**:
   - Builds directed flow graph from Pega flow JSON shapes and connectors.
   - Simulates work item navigation and routing condition evaluation locally.

3. **`decision/` (Decision Table & Tree Evaluator)**:
   - Evaluates decision table conditions in priority order and traverses decision tree nodes locally.

4. **`ui/` (Section & Harness UI Preview)**:
   - Renders HTML previews of Pega sections/harnesses locally.

5. **`security/` (Security Sandbox)**:
   - Sandboxes local expression evaluation with timeouts and function whitelists.
